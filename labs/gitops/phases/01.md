# Phase 01: 쿠버네티스 수동 배포

### 1. 쿠버네티스 매니페스트 생성 

> 1) Deployment
> 2) Service
> 3) apply
> 4) port-forward svc

매니페스트 저장용 디렉터리 생성:
```sh
cd lab-gitops
mkdir -p k8s
```

이 랩은 GitOps에 집중하기 위해 별도의 애플리케이션을 만들지 말고, **nginx** 하나로 단순하게 감.

Deployment 매니페스트 생성:
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: gitops-demo
spec:
  replicas: 2
  selector:
    matchLabels:
      app: gitops-demo
  template:
    metadata:
      name: gitops-demo
      labels:
        app: gitops-demo
    spec:
      containers:
        - name: nginx
          image: nginx:1.29
          ports:
            - containerPort: 80
```

확인:
```sh
cat k8s/deployment.yaml
```

### 2. Service 매니페스트 생성

k8s/service.yaml 생성:
```yaml
apiVersion: v1
kind: Service
metadata:
  name: gitops-demo
spec:
  selector:
    app: gitops-demo
  ports:
    - port: 80
      targetPort: 80
```

확인:
```sh
cat k8s/service.yaml
```

### 3. 수동 배포

GitOps 붙이기 전 기준 상태를 만들기 위해 먼저 직접 배포함.

매니페스트 적용:
```sh
kubectl apply -f k8s
```

확인:
```sh
kubectl get deploy
kubectl get pod
kubectl get svc
```

---

아직 이 상태는 GitOps가 아님:
```txt
Manifest(local)
    ↓
kubectl apply
    ↓
Kubernetes
```
즉, 사람이 직접 클러스터에 반영한 상태.

### 4. nginx 응답 확인

Service를 로컬로 포트포워딩:
```sh
kubectl port-forward svc/gitops-demo 8080:80
```

다른 터미널에서 확인:
```sh
curl localhost:8080
```
결과는 nginx 기본 페이지 응답
