# Phase 02: Argo CD 설치

> 1) Argo CD 전용 Namespace 생성
> 2) Argo CD 설치
> 3) Argo CD Server 접근

### 1. Argo CD Namespace 생성

Argo CD 관련 리소스를 분리해서 관리하기 위해 전용 Namespace 생성:
```sh
kubectl create ns argocd
```

확인:
```sh
kubectl get ns argocd
```

### 2. Argo CD 설치

공식 설치 매니페스트를 `argocd` Namespace에 적용:
- https://argo-cd.readthedocs.io/en/stable/getting_started/ 참조
```sh
kubectl apply -n argocd \
  --server-side \
  --force-conflicts \
  -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
```

설치 후 Pod 확인:
```sh
kubectl get pod -n argocd
```
- 생성 직후에는 일부 Pod가 `ContainerCreating` 또는 `Init` 상태일 수 있음.

상태 변화 확인:
```sh
kubectl get pod -n argocd -w
```
- 주요 Pod가 1/1 Running 상태로 올라오면 설치 완료로 봄.

Pod 별 역할:
- argocd-server → UI/API 서버
- argocd-repo-server → Git repo를 읽고 manifest 생성
- argocd-application-controller → 실제 클러스터 상태와 Git 상태 비교/동기화
- argocd-redis → 내부 캐시
- applicationset-controller → 여러 Application 생성/관리
- dex-server → 외부 인증 연동
- notifications-controller → 알림

### 3. Argo CD Server 접근

<u>기본 설치에서는 `argocd-server`가 ClusterIP이므로 클러스터 외부에서 바로 접근할 수 없음.</u>
따라서 로컬에서 접근하기 위해 **포트포워딩**이 필요함.

먼저 확인:
```sh
kubectl get svc -n argocd argocd-server
```

포트포워딩
```sh
kubectl port-forward -n argocd svc/argocd-server 8080:443
```

이후, 브라우저에서 https://localhost:8080으로 접속하면 됨.
(인증서 경고가 뜨는 건 로컬 실습 환경에서는 정상)

로그인 계정은:
```txt
admin
```

초기 비밀번호는 k8s Secret에 자동 생성되어 있음:
```sh
kubectl get secret -n argocd argocd-initial-admin-secret \
  -o jsonpath="{.data.password}" | base64 -d; echo
```

브라우저에서 https://localhost:8080으로 접속.

이후, admin 계정으로 로그인하여 Argo CD UI 접근 확인.

---

여기까지 작업한 걸 생각해보자.

현재 상태를 정확히 표현하면:
```txt
GitHub
└── engineering
    └── labs
        └── gitops
            └── k8s/*.yaml

Kubernetes
└── nginx
    └── kubectl apply로 수동 배포

Argo CD
└── 설치 및 로그인 완료
```
즉, 세 요소가 각각 존재할 뿐임.
아직 GitOps 파이프라인으로 연결되지 않은 상태임.

따라서 현재 필요한 것은:
```txt
  GitHub     ← Desired State
    ↓ watch
  Argo CD    ← Reconciliation
    ↓ sync
Kubernetes   ← Actual State
```
가 완성되는 것임.

지금 시점의 핵심은 GitHub도 있고, Argo CD도 있고, Kubernetes workload도 있지만,
'아직 서로 GitOps 관계가 아니다'가 정확함.
